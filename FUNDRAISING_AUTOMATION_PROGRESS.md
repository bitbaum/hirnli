**API Endpoints:**

#### Foundations
```
GET    /api/foundations              # List with filters
POST   /api/foundations              # Create new foundation
GET    /api/foundations/[id]         # Get single foundation
PATCH  /api/foundations/[id]         # Update foundation
DELETE /api/foundations/[id]         # Archive foundation (soft delete)
POST   /api/foundations/import       # Bulk import from JSON file
```

**Query Parameters:**
- `q`: Search by name
- `fitMin`: Filter by minimum fit score (0-10)
- `priority`: Filter by priority (1-4)
- `archived`: Include archived foundations
- `limit`: Results per page (default: 50, max: 100)
- `offset`: Pagination offset

**Example Usage:**
```bash
# List high-fit foundations
curl "http://localhost:3000/api/foundations?fitMin=7"

# Search by name
curl "http://localhost:3000/api/foundations?q=volkart"

# Create foundation
curl -X POST http://localhost:3000/api/foundations \
  -H "Content-Type: application/json" \
  -d '{"name":"Test Stiftung","fitScore":8}'

# Bulk import
curl -X POST http://localhost:3000/api/foundations/import \
  -F "file=@foundation-batch.json"
```

#### Applications
```
GET    /api/applications             # List with filters
POST   /api/applications             # Create new application
GET    /api/applications/[id]        # Get single application
PATCH  /api/applications/[id]        # Update application
DELETE /api/applications/[id]        # Delete application
GET    /api/applications/dashboard   # KPI statistics
```

**Query Parameters:**
- `status`: Filter by status (prospect, draft, submitted, etc.)
- `foundationId`: Filter by foundation
- `assignedTo`: Filter by assigned person
- `priority`: Filter by priority (1-4)
- `limit`: Results per page
- `offset`: Pagination offset

**Example Usage:**
```bash
# List all applications
curl http://localhost:3000/api/applications

# Create application
curl -X POST http://localhost:3000/api/applications \
  -H "Content-Type: application/json" \
  -d '{
    "foundationId":"volkart-stiftung",
    "requestedAmount":50000,
    "status":"prospect"
  }'

# Get dashboard stats
curl http://localhost:3000/api/applications/dashboard
```

**Response Format:**
```typescript
// Success
{
  success: true,
  data: {...},
  meta?: { total, limit, offset, hasMore }
}

// Error
{
  success: false,
  error: "Message",
  details?: {...}
}
```

## Architecture Decisions

### Why Turso?
- Hosted SQLite (no server management)
- Edge replication (fast worldwide)
- Generous free tier (9 GB, 500 databases)
- Native SQL (no ORM lock-in)

### Why Drizzle?
- Type-safe (types derived from schema)
- Simple API (SQL-like)
- Lightweight (no bloat)
- Great TypeScript support

### Why nanoid?
- Short IDs (21 characters vs 36 for UUID)
- URL-safe (no special characters)
- Collision-resistant

### API Design Principles
- RESTful routes (`/api/{resource}`, `/api/{resource}/{id}`)
- Standard response format (`{ success, data, meta }`)
- Query parameters for filters (not request body on GET)
- Activity logging on all mutations (audit trail)
- Soft deletes where possible (preserve history)
