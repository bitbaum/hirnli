# Deployment — Self-Hosted Hetzner (bitbaum)

Since 2026-06-12 this app is self-hosted (Vercel/Neon exit). One box runs
everything; this doc is the complete, reproducible picture.

## Topology

| Piece | Value |
|-------|-------|
| Box | `root@167.233.22.31` (Hetzner CX43, hostname `bitbaum`) |
| App dir | `/opt/revamp-info/app` (Next.js standalone output + `.env`) |
| Service | `revamp-info-app.service` (systemd, runs `launch.sh`, port **4012**) |
| Reverse proxy | Caddy → `https://revamp-info.orangecat.ch` (auto-TLS) |
| Database | Shared `revampit` PostgreSQL on the box (localhost:5432). All tables prefixed `fundraising_` |
| Crons | systemd timers `appcron-revamp-info-{deadline-reminder,data-quality}` → hit `/api/cron/*` with `CRON_SECRET` bearer auth |

The box-side units (service, timers, Caddy block) are generated by the fleet
tooling in `fleetcrown/scripts/hetzner/` (`sync-infra.sh`, `install-app-crons.sh`)
from its `apps.conf` entry:

```
revamp-info|4012|revamp-info.orangecat.ch|/home/g/dev/revamp-info|.|revampit
```

## Deploying

The standard path is the fleet deploy script (build locally → rsync artifact →
restart → health check). The box cannot build (OOM); always build off-box.

```bash
~/dev/fleetcrown/scripts/hetzner/deploy.sh revamp-info
```

What it does:
1. Sources `.env.selfhost.local`, opens an SSH tunnel so build-time DB access
   (the `prebuild` sync + SSG) hits the box's Postgres.
2. `SELF_HOST=1 npm run build` (runs `npm run sync` first — DB → `stiftungen-generated.ts`).
3. Stages `.next/standalone` + `.next/static` + `public/`, rsyncs to
   `/opt/revamp-info/app/` (never touches `.env` / `launch.sh` on the box).
4. `systemctl restart revamp-info-app`, then checks `http://localhost:4012/`.

Afterwards verify the public URL: `curl -sI https://revamp-info.orangecat.ch`.

## Runtime environment (`/opt/revamp-info/app/.env`)

| Var | Purpose |
|-----|---------|
| `DATABASE_URL` | Shared revampit Postgres (localhost) |
| `INTERNAL_PASSWORD` | HTTP Basic Auth for `/fundraising/**` + internal APIs when set. |
| `INTERNAL_AUTH` | `off` = everything public (explicit demo-phase choice, currently active). If neither this nor `INTERNAL_PASSWORD` is set, production fails closed (503 on internal routes). |
| `SHARE_SECRET` | HMAC key for public `/gesuch/share/[token]` pages. Rotating it invalidates every previously sent share link. |
| `CRON_SECRET` | Bearer token the appcron timers send to `/api/cron/*` |
| `GROQ_API_KEY` | LLM rewrite endpoint (`/api/ai/gesuch-section`) |
| `RESEND_API_KEY` | Optional — cron email notifications. Unset = crons run but skip email (requires a Resend account with `revamp-it.ch` domain verified). |
| `AUTH_TRUST_HOST` | Next.js behind reverse proxy |

Local dev mirrors these in `.env.local` (gitignored). The box env is SSOT for
production values; never overwrite it blindly — `deploy.sh` only uploads env
on first install or with `--env`.

## Database access from a dev machine

Postgres only listens on the box's localhost. Tunnel first:

```bash
ssh -N -L 15432:127.0.0.1:5432 root@167.233.22.31 &
# .env.local DATABASE_URL points at 127.0.0.1:15432
npm run sync    # refresh generated foundation cache from prod DB
npm run audit   # live pipeline funnel report
```

## Migrations

Drizzle migration SQL lives in `src/lib/db/migrations/`. Because the DB is
shared with revampit (whose own drizzle bookkeeping owns the `drizzle` schema),
apply revamp-info migrations by hand — they are written to be idempotent and
additive:

```bash
ssh root@167.233.22.31 "sudo -u postgres psql -d revampit -v ON_ERROR_STOP=1 -f -" \
  < src/lib/db/migrations/00XX_name.sql
```

Never edit an applied migration; always add a new numbered file plus a
`_journal.json` entry.

## CI

`.github/workflows/ci.yml` runs typecheck + lint + build on every push/PR.
CI has no DB access, so the build runs with `SKIP_SYNC=true` and uses the
committed `stiftungen-generated.ts`.
